# Scope and MVP

FSD Part 2 — Scope, MVP Features, Future Features & User Journeys
Project Name
New Earth Command Dashboard
Document Version
V0.1 — Scope and User Journey Draft
________________________________________
1. Product Scope
The New Earth Command Dashboard will be a personal dashboard app for managing the daily build of New Earth.
It will bring together:
•	daily planning 
•	project tracking 
•	task management 
•	learning 
•	business actions 
•	content planning 
•	build journaling 
•	wellbeing 
•	vision alignment 
The app will begin as a personal command centre for Peter, then later expand into a more advanced system with AI assistance, calendar integration, cloud sync, and possible wider use.
________________________________________
2. MVP Scope
The MVP is the first usable version of the app.
The MVP should focus on one main outcome:
Help Peter open the app each morning and know exactly what matters today.
The MVP should include only the features needed to create daily clarity and project momentum.
________________________________________
3. MVP Feature List
3.1 Daily Dashboard
The Daily Dashboard is the main home screen.
It should show:
Today’s date
Main focus for today
Top 3 priority tasks
Active projects
Learning focus
Content focus
Wellbeing check-in
Quick notes
End-of-day review
Purpose:
To give the user one clear place to start the day.

3.4 Top 3 Daily Priorities
Each day, the user should select up to three key tasks.
These are shown at the top of the Daily Dashboard.
Rules:
Only 3 main tasks per day
Each task should connect to a project
Each task should have a clear outcome
Tasks can be moved, completed, or carried forward
Purpose:
To prevent overwhelm and create focused progress.
________________________________________
3.5 Daily Planner
The Daily Planner helps structure the working day.
It should include:
Morning intention
Main focus
Top 3 priorities
Time blocks
Learning block
Content block
Wellbeing block
Evening review
Example:
Morning Intention:
Move MicroGrow Field Scanner forward without getting distracted.

Main Focus:
Build the diagnostics screen.

Top 3:
1. Create UI layout
2. Test Bluetooth/WiFi connection status display
3. Write LinkedIn progress update

Evening Review:
What moved forward?
What blocked me?
What is tomorrow’s next action?
Purpose:
To turn the day into a simple, guided build session.

4. Out of Scope for MVP
The MVP should not include:
Cloud sync
Multiple user accounts
Advanced AI
Team collaboration
Payment systems
Full CRM
Full accounting
Automated social media posting
Deep analytics
Complex calendar integration
Advanced permissions
Public marketplace
These can be considered later.
The first version must stay simple and useful.

6. User Journeys
User Journey 1 — Morning Planning
Goal
Peter opens the app and decides what matters today.
Flow
1. Open app
2. See Daily Dashboard
3. Review active projects
4. Choose today’s main focus
5. Select top 3 tasks
6. Add learning focus
7. Add content focus
8. Add wellbeing intention
9. Start work
Success Outcome
Peter knows exactly what he is working on today.
________________________________________
User Journey 2 — Capturing a New Task
Goal
Peter has an idea or task and wants to capture it quickly.
Flow
1. Tap Quick Capture
2. Enter task title
3. Choose project
4. Choose category
5. Set priority
6. Save to Inbox or Today
Success Outcome
The task is captured without distracting from current work.
________________________________________
User Journey 3 — Working on MicroGrow
Goal
Peter wants to move MicroGrow forward.
Flow
1. Open Project Hub
2. Select MicroGrow
3. View current milestone
4. View active tasks
5. Choose next action
6. Mark task In Progress
7. Add notes while working
8. Mark task Done
9. Add journal entry
Success Outcome
MicroGrow progress is visible and recorded.
________________________________________
User Journey 4 — Learning Something New
Goal
Peter needs to learn something to complete a project.
Flow
1. Open Learning Tracker
2. Add or select topic
3. Link learning to a project
4. Add resource
5. Add notes
6. Create practice task
7. Mark learning as Applied when used
Success Outcome
Learning becomes practical and project-linked.
________________________________________
User Journey 5 — Creating a LinkedIn Update
Goal
Peter wants to turn progress into public awareness.
Flow
1. Open Build Journal
2. Select recent entry
3. Mark as possible LinkedIn post
4. Open Content Planner
5. Create draft post
6. Add image requirement
7. Mark as Ready
8. Publish manually
9. Mark as Published
Success Outcome
Daily progress becomes content without starting from scratch.
________________________________________
User Journey 6 — End-of-Day Review
Goal
Peter reviews what moved forward.
Flow
1. Open Daily Planner
2. Review top 3 tasks
3. Mark completed items
4. Carry forward unfinished items
5. Add build journal entry
6. Record lessons learned
7. Add tomorrow’s possible focus
8. Complete wellbeing check-in
Success Outcome
The day ends with clarity, progress, and a next step.
________________________________________
User Journey 7 — Managing Business/Funding
Goal
Peter tracks money-making or funding actions.
Flow
1. Open Business & Funding Hub
2. Add opportunity
3. Set deadline or follow-up date
4. Link CV/document if needed
5. Add next action
6. Update status as progress happens
Success Outcome
Funding and business actions do not get lost.
________________________________________
User Journey 8 — Feeling Overwhelmed
Goal
Peter opens the app when he feels lost.
Flow
1. Open Daily Dashboard
2. Tap Reset Focus
3. App shows active projects
4. User selects one main focus
5. App suggests choosing only 1 to 3 tasks
6. User parks non-urgent tasks
7. App creates a simplified day plan
Success Outcome
The app helps reduce overwhelm instead of adding more pressure.
________________________________________
7. MVP User Flow Summary
The MVP should follow this simple daily loop:
Plan the day
Choose top 3 tasks
Work on one project at a time
Capture notes and progress
Review the day
Carry forward what matters
This loop is the heart of the app.
________________________________________
8. MVP Priority Order
The first build should be created in this order:
1. Basic app shell
2. Dashboard screen
3. Project system
4. Task system
5. Daily planner
6. Journal
7. Learning tracker
8. Content planner
9. Business hub
10. Wellbeing check-in
This order gives the app structure before adding deeper features.
________________________________________
9. MVP Success Definition
Version 0.1 is successful when Peter can:
1. Open the app.
2. See today’s focus.
3. Choose top 3 tasks.
4. View active New Earth projects.
5. Add tasks.
6. Mark tasks complete.
7. Write a daily build journal entry.
8. Track learning.
9. Capture content ideas.
10. End the day knowing what moved forward.
________________________________________
10. Scope Principle
The scope principle for the first version is:
Build the smallest useful command centre first.
Do not build every possible feature.
Build the version that creates immediate clarity.

# Omega Experiment Workspace Roadmap

This roadmap keeps the experiment workspace practical, calm, and genuinely useful.

The goal is to turn experiments into a repeatable local learning loop:

- define the question
- run the test
- capture evidence
- record the result
- carry the lesson forward

## Roadmap

### 1. Clarify The Workspace Lifecycle

Make the workspace easier to scan by giving experiments a simple, honest lifecycle.

Focus:

- Draft
- Ready
- Running
- Review needed
- Lesson captured
- Parked or archived

Why this matters:

It helps the workspace show what needs attention first without adding extra noise.

### 2. Link Experiments To The Rest Of The Dashboard

Connect experiments back to the project system so the work stays reusable.

Focus:

- link each experiment to one project
- link related tasks
- link related journal entries
- link follow-up content or notes

Why this matters:

This keeps experiments from becoming isolated notes and makes them useful to the wider dashboard.

### 3. Strengthen Evidence Capture

Make it easier to capture and review what actually happened during a test.

Focus:

- attach screenshots, files, or notes
- tag evidence by type
- mark evidence as verified
- filter experiments by evidence presence

Why this matters:

The workspace becomes more trustworthy when the result is backed by visible proof.

### 4. Add Experiment Templates

Make the first step faster by giving the user reusable starters.

Focus:

- project validation
- hardware or build test
- workflow test
- learning experiment
- research check

Why this matters:

Templates reduce setup friction and make the workspace feel ready to use instead of blank.

### 5. Turn Results Into Reuse

Make the outcome of an experiment flow into the rest of the app.

Focus:

- compare experiments side by side
- surface repeated lessons
- suggest the next action
- convert a finished experiment into a task, journal note, or content idea

Why this matters:

The workspace becomes a learning engine instead of a static archive.

### 6. Generate Experiment Reports

Make it easy to turn the current workspace into a local markdown report.

Focus:

- generate a calm markdown workspace summary
- include the latest experiments and repeated lesson themes
- save reports into the local storage folder
- copy the generated report for reuse elsewhere

Why this matters:

Reports turn the experiment workspace into something that can be reviewed, shared, and carried forward without rebuilding the same summary by hand.

### 7. Save Selected Comparisons

Make selected experiment comparisons exportable as a reusable local markdown file.

Focus:

- save the selected pair comparison into the reports folder
- keep the file naming tied to the chosen experiments
- preserve the copy-to-clipboard flow

Why this matters:

It gives the comparison picker a durable output that can be reused in notes, reports, or follow-up work.

### 8. Browse Saved Reports

Make the saved report archive visible and easy to open from the workspace.

Focus:

- list saved report files in the Reports section
- open any saved markdown report with one click
- keep the archive sorted by newest first

Why this matters:

Saved reports only help if the user can find them again without leaving the workspace.

## Recommended Build Order

1. Lifecycle and labels.
2. Project and task linking.
3. Evidence capture and filters.
4. Templates and quick starts.
5. Result reuse and comparison.
6. Report generation and export.
7. Selected comparison export.
8. Saved report browsing.

## Success Pattern

The workspace is working well when the user can open it, understand what needs attention, run a test, attach proof, and turn the outcome into the next practical step without feeling overloaded.

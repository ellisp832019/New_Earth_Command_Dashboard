# Dashboard Ranked Roadmap

This is the strictest build order for the current New Earth Dashboard landscape.

It is meant to answer one question clearly:

What should we build or harden first if we want the system to become steadier with the least extra maintenance?

## Rank 1 - Stabilize The Core Loop

Keep the everyday surfaces solid first:

- Dashboard
- Tasks
- Planner
- Projects
- Inbox / Quick Capture

Why first:

- This is the daily control loop.
- If this is calm, the rest of the system has somewhere reliable to land.

## Rank 2 - Finish Treasury

Keep Treasury on the main path and complete its calm local-first workflow:

- home
- wizard
- drafts
- file safety
- receipts
- spend
- subscriptions
- decisions
- summaries

Why second:

- Treasury affects real operating discipline.
- It needs to feel safe and contained before it becomes busier.

## Rank 3 - Keep Backup Guardian Self-Sufficient

Do not over-expand it; just finish the remaining useful gaps that make it boring and dependable:

- history
- restore points
- retention
- verification
- health surfacing

Why third:

- Backup is a system guardrail.
- It should reduce risk without becoming another maintenance burden.

## Rank 4 - Harden Assets, QR Labels, And Visual Capture Together

Treat these as one operational lane:

- Asset Intelligence
- QR Labels
- Visual Capture

Why here:

- Assets, labels, and evidence all connect.
- They are most useful when the folder paths, capture flow, and label flow work together.

## Rank 5 - Finish Knowledge Engine And Repo Research Engine

These are the main knowledge and analysis tools:

- Knowledge Engine
- Repo Research Engine

Why here:

- They strengthen research, cataloguing, and understanding across the system.
- They are powerful, but they do not need to outrank the daily operating loop.

## Rank 6 - Polish Voice Assistant

Complete the next voice work in order:

- desktop hardening
- capture history
- shortcut templates
- remembered threads
- briefing clarity
- follow-up chips
- shared session state

Why here:

- Voice is already valuable.
- The remaining work is mostly reliability, reuse, and calmer turn handling.

## Rank 7 - Add Meeting System As A Local Workflow

Keep meetings simple and local-first:

- meeting index
- meeting notes
- decisions
- actions
- follow-ups

Why here:

- It supports real working life.
- But it should start as a file-first workflow, not a heavy platform.

## Rank 8 - Keep Command Deck As A Workflow Multiplier

Make the software Command Deck useful before any physical hardware expansion:

- shortcut bridge
- folder/actions launcher
- meeting helper actions
- local workflow control

Why here:

- It improves speed and control.
- It should stay a multiplier, not become a separate maintenance project.

## Rank 9 - Keep Launchpad And Project Repo Bridge Available, But Secondary

These are valuable, but they are not the core daily loop:

- Launchpad
- Project Repo Bridge

Why here:

- They are meaningful expansion modules.
- They should not pull attention away from the stronger operational systems.

## Rank 10 - Leave Broad Integrations Parked

Keep these out of the active build path until the local-first core is clearly stable:

- cloud sync
- login/account systems for V0.1
- live GitHub integration
- live WordPress integration
- live calendar integration
- heavy AI automation without a safe adapter
- native Bluetooth printing as the first QR path

Why last:

- They add complexity, coupling, and support cost.
- They are better once the core has earned them.

## Practical Rule

If a new idea does not clearly improve one of the first five ranks, it probably belongs in parked or later territory.

# Repo Upgrade Roadmap

This roadmap summarizes where the repo is now and what the major upgrade direction looks like across the whole system.

It is intentionally broader than `TASK.md`.
It helps answer: what is the next major layer after the current core is stable?

## Current Position

The repo is no longer just an app shell.

It now has:

- a working Flutter dashboard core
- a clear local-first direction
- active Users & Devices controls
- Treasury and other core modules in active development
- module hub and specialist module surfaces
- a growing docs-and-roadmap stack

That means the next upgrades should focus on strengthening the core, then bringing adjacent modules online in a steady order.

## Upgrade Principles

1. Keep the daily dashboard calm.
2. Strengthen the operating core before broad expansion.
3. Keep local-first data and review-first flows.
4. Add new surfaces only when they have a clear health or recovery path.
5. Park anything that competes with the core loop.

## Major Upgrade Phases

### Phase 1 - Core working day

Focus:

- Dashboard clarity
- Tasks and Planner
- Projects
- Quick capture
- Users & Devices trust and session flow

Outcome:

- the app helps with the daily working loop before anything else gets fancier

### Phase 2 - Safety and finance discipline

Focus:

- Treasury hardening
- Backup Guardian reliability
- session visibility
- access gating

Outcome:

- the app protects real decisions and remains dependable under pressure

### Phase 3 - Operational capture lane

Focus:

- Asset Intelligence
- QR Labels
- Visual Capture

Outcome:

- the app becomes a practical tool for real-world evidence, assets, and print/capture workflows

### Phase 4 - Knowledge and research

Focus:

- Knowledge Engine
- Omega Knowledge Engine
- Repo Research Engine

Outcome:

- the app can explain repositories, learn from the codebase, and generate useful documentation safely

### Phase 5 - Coordination and follow-through

Focus:

- Meeting System
- Command Deck
- Launchpad
- Project Repo Bridge

Outcome:

- the app supports coordination, launch work, and workflow acceleration

### Phase 6 - Export, memory, and wider integration

Focus:

- NE Obsidian Sync
- exports
- long-term project memory
- safe future integration adapters

Outcome:

- the system can produce durable records and reuse knowledge across projects

## What Should Stay Parked

Keep these out of the next active upgrade waves:

- cloud sync
- login and account systems for V0.1
- live GitHub integration
- live WordPress integration
- live calendar integration
- heavy AI automation without a safe adapter
- native Bluetooth printing as the first QR path

## Where The Repo Is Now

Based on the current docs, the repo is between:

- core MVP completion
- and the first wave of stable specialist modules

The biggest signal is this:

- the dashboard is real enough to use
- the supporting modules are real enough to route into
- but the system still needs disciplined hardening before it becomes a broader operating platform

## Best Next Moves

1. Finish the most fragile core surfaces first.
2. Harden Treasury and Backup paths.
3. Keep Users & Devices clean, well-documented, and secure.
4. Bring asset and capture modules online only after the core remains calm.
5. Let the knowledge stack grow after the operational lanes are steady.

# Dashboard Module First Week Plan

This is the practical follow-on to the activation roadmap.

It answers a narrower question:

What should we do first for each module so it starts becoming active with the core instead of staying as a plan?

## How To Use This Plan

- Work top to bottom.
- Do not jump ahead just because a later module looks exciting.
- Stop at the first useful slice for each module.
- Keep every step local-first, review-first, and calm.

## Week 1 Focus

### 1. Treasury

First tasks:

- confirm the current finance folder path
- verify the Treasury home screen loads local state
- make sure the draft/wizard path is resumable
- surface a visible folder health status

Success check:

- Hayley can open Treasury, see whether the folder is healthy, and continue a draft without confusion.

### 2. Voice Assistant

First tasks:

- confirm the desktop capture path is stable
- expose the recent capture history
- make the first shortcut templates easy to reuse
- keep the remembered thread visible

Success check:

- a recent voice command can be reused or continued without re-speaking everything.

### 3. Backup Guardian

First tasks:

- confirm the current backup target path
- show latest health and verification clearly
- make the open folder and latest report actions obvious
- keep restore point history visible

Success check:

- the module feels reliable and boring, with no mystery around backup status.

### 4. Asset Intelligence

First tasks:

- read the asset path from local config
- validate folder health
- show a simple home summary
- list the core asset registers that already exist or are planned

Success check:

- the user can see where asset data lives and what the asset module currently knows.

### 5. QR Labels

First tasks:

- confirm the QR folder paths
- make QR generation start from asset id only
- show label preview before queueing
- keep printer profiles editable as data, not hardware logic

Success check:

- an asset can produce a label draft and queue entry without requiring native printer support yet.

### 6. Visual Capture

First tasks:

- confirm the capture folder path
- build the capture inbox entry point
- allow file import into the inbox
- make image linking to Treasury or Assets visible

Success check:

- a photo or receipt image can be brought into the system and tied to something useful.

### 7. Knowledge Engine

First tasks:

- show the library page inside the Dashboard
- add search
- open a single item detail view
- expose health and extraction progress

Success check:

- the knowledge library feels like a usable read-only reference surface, not just a backend job.

### 8. Repo Research Engine

First tasks:

- surface the repo research landing page
- show the latest scan/report summary
- expose repo comparison and report viewing
- keep the module clearly safe and read-only by default

Success check:

- the user can inspect a repo, read the result, and trust that nothing ran.

### 9. Meeting System

First tasks:

- create the meeting index pattern
- create a simple local note file flow
- make new meeting creation obvious
- keep actions and decisions visible

Success check:

- a meeting can be captured as a local file-first record without needing a separate platform.

### 10. Command Deck

First tasks:

- surface a software-only command deck page
- map a few useful shortcuts
- add quick launch actions for core dashboard routes
- keep the deck obviously supportive, not separate

Success check:

- the deck saves time by launching useful actions cleanly.

### 11. Project Repo Bridge

First tasks:

- map the current project and repo data sources
- keep the bridge read-only
- show a basic project intelligence summary
- avoid overwriting dashboard data

Success check:

- the bridge can explain what it sees without taking ownership of the source data.

### 12. Launchpad

First tasks:

- open the seeded campaign record
- show readiness and reward data
- keep finance and fulfilment surfaces local
- keep the launch flow calm and compact

Success check:

- the module feels like a practical campaign cockpit, not a marketing site.

### 13. NE Obsidian Sync

First tasks:

- export current state
- export architecture
- export roadmap
- export decisions

Success check:

- long-term memory exports can be produced from the project without manual copying.

## Best Weekly Order

If this is a single focused week, the best order is:

1. Treasury
2. Voice Assistant
3. Backup Guardian
4. Asset Intelligence
5. QR Labels
6. Visual Capture

That sequence gives the biggest return first because it strengthens the operating core, the safety net, and the real-world capture lanes before widening into knowledge and coordination tools.

## Do Not Start Yet

- cloud sync
- login systems for V0.1
- live GitHub integration
- live WordPress integration
- live calendar integration
- heavy AI automation without a safe adapter
- native Bluetooth printing as the first label path

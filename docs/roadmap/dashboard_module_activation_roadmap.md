# Dashboard Module Activation Roadmap

This roadmap is the next-step plan for bringing more New Earth modules online in active state with the core Dashboard.

It is not a list of every future idea.
It is the practical order for turning roadmap modules into working, visible, low-friction parts of the daily system.

## Activation Rule

A module becomes `active with the core` when all three are true:

1. It appears in the Dashboard in a calm, discoverable way.
2. It reads and writes local-first data safely.
3. It has a clear health, review, or recovery path so it does not become fragile.

## Phase 1 - Finish The Core Operating Loop

These surfaces should stay first because they support the daily command centre.

### 1. Treasury

Bring Treasury fully into the active core.

Why:

- It affects real operating decisions.
- It needs to feel safe, calm, and predictable.

Activation targets:

- home
- wizard
- local drafts
- folder health
- receipts
- project spend
- subscriptions
- decisions
- monthly summary

### 2. Voice Assistant

Keep Voice Assistant active, but finish the reliability layer before it expands.

Why:

- It is already a powerful capture surface.
- It needs a single stable turn-taking path.

Activation targets:

- desktop hardening
- capture history
- shortcut templates
- remembered thread support
- briefing clarity
- follow-up chips
- shared session state

### 3. Backup Guardian

Keep Backup Guardian active as a system guardrail.

Why:

- It protects everything else.
- It should stay boring and dependable.

Activation targets:

- health status
- history
- restore points
- retention
- verification
- open folder and report actions

## Phase 2 - Bring The Operational Trio Online

These three modules should come online together because they share paths, safety concerns, and practical value.

### 4. Asset Intelligence

Bring asset tracking into the active core.

Why:

- It supports inventory, equipment, and operational tracking.
- It links naturally to Treasury and QR labels.

Activation targets:

- config and path health
- home summary
- register views
- quick capture
- valuation and insurance summaries

### 5. QR Labels

Bring QR labels online as part of Asset Intelligence.

Why:

- Labels make asset tracking visible and usable in the real world.
- The workflow should stay local and manual first.

Activation targets:

- QR generation
- preview
- print queue
- label register
- printer profiles
- scan lookup

### 6. Visual Capture

Bring Visual Capture online as the evidence and photo intake lane.

Why:

- It completes the asset and Treasury loop.
- It gives receipts, parts, and project evidence a calm home.

Activation targets:

- folder health
- capture inbox
- file import
- image preview
- linking to Treasury, assets, projects, and QR labels

## Phase 3 - Bring The Knowledge Stack Online

These are the modules that turn raw files and repos into understanding.

### 7. Knowledge Engine

Bring the knowledge library into active dashboard use.

Why:

- It is a core knowledge surface for the Omega OS library.
- It helps the Dashboard become more than a task tool.

Activation targets:

- library page
- search
- item detail
- health/stats
- extraction progress

### 8. Repo Research Engine

Bring repository analysis into the active core as a safe research tool.

Why:

- It helps the system understand code and project structure.
- It is already a strong local-first analysis layer.

Activation targets:

- dashboard page
- repo detail pages
- comparison flow
- report viewing
- follow-on review actions

## Phase 4 - Bring Coordination Tools Into The Core

These modules help the system coordinate people, tasks, and workflows.

### 9. Meeting System

Bring meetings into the core as a file-first workflow.

Why:

- It supports decisions, actions, and follow-up.
- It should stay local and simple first.

Activation targets:

- meeting index
- meeting notes
- actions
- decisions
- transcript import later

### 10. Command Deck

Bring the software Command Deck online as a workflow accelerator.

Why:

- It makes the rest of the system faster to operate.
- It should support the Dashboard, not compete with it.

Activation targets:

- virtual deck page
- shortcuts
- folder/action launchers
- meeting helpers
- workflow buttons

## Phase 5 - Bring Expansion Modules Online Only After The Core Is Stable

These modules are useful, but they should come after the operating core is solid.

### 11. Project Repo Bridge

Activation targets:

- project and repo mapping
- local progress logs
- safe read-only sync views

### 12. Launchpad

Activation targets:

- campaign management
- reward/readiness tracking
- finance and fulfilment views

### 13. NE Obsidian Sync

Activation targets:

- current state export
- architecture export
- roadmap export
- decision export

## Phase 6 - Keep Broader Integrations Parked

Do not move these into the active core yet:

- cloud sync
- login and account systems for V0.1
- live GitHub integration
- live WordPress integration
- live calendar integration
- heavy AI automation without a safe adapter
- native Bluetooth printing as the first QR path

## Recommended Build Order

If the goal is to bring modules online with the least risk, build in this order:

1. Treasury
2. Voice Assistant
3. Backup Guardian
4. Asset Intelligence
5. QR Labels
6. Visual Capture
7. Knowledge Engine
8. Repo Research Engine
9. Meeting System
10. Command Deck
11. Project Repo Bridge
12. Launchpad
13. NE Obsidian Sync

## Simple Test For Readiness

Before a module moves into active core status, check that:

- it has a clear dashboard entry point
- its local path or data source is visible
- the user can review before committing changes
- the module has a calm empty state and a clear health state
- the module does not break the main Dashboard loop

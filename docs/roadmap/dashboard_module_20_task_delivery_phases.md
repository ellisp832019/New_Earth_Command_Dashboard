# Dashboard Module 20-Task Delivery Phases

This breaks the 20-task execution queue into four delivery phases.

The goal is to keep each phase coherent:

- Phase 1 hardens the operating core
- Phase 2 brings the real-world capture lane online
- Phase 3 activates the knowledge and research layer
- Phase 4 adds coordination and expansion tools

## Phase 1 - Operating Core

These tasks make the dashboard safer and more useful for daily work.

1. Treasury folder health and path visibility
2. Treasury resumable draft and wizard flow
3. Treasury summary and decision surfaces
4. Voice Assistant capture history
5. Voice Assistant remembered thread and briefing flow
6. Voice Assistant shared session state polish
7. Backup Guardian history and restore point surfacing
8. Backup Guardian open-folder and report actions

Why this phase first:

- It strengthens the daily control loop.
- It keeps finance, voice, and backup dependable before the system expands.

## Phase 2 - Capture And Asset Lane

These tasks connect assets, labels, and evidence into one operational lane.

9. Asset Intelligence config and health check
10. Asset Intelligence home and register views
11. QR Labels generation and label preview
12. QR Labels print queue and printer profiles
13. Visual Capture inbox and import flow
14. Visual Capture linking to Treasury and Assets

Why this phase second:

- It gives the system practical real-world capture tools.
- It links finance, assets, and evidence together cleanly.

## Phase 3 - Knowledge And Research

These tasks make the Dashboard more useful for understanding files and code.

15. Knowledge Engine library page and health view
16. Knowledge Engine search and item detail
17. Repo Research Engine dashboard page and report viewing
18. Repo Research Engine comparison and review flow

Why this phase third:

- It turns library and repo data into something the Dashboard can actually use.
- It adds insight without disturbing the core operating loop.

## Phase 4 - Coordination And Expansion

These tasks round out the system once the core is already stable.

19. Meeting System file-first index and note flow
20. Command Deck software page and quick-launch actions

Why this phase last:

- These are useful multipliers.
- They work best when the core modules are already calm and reliable.

## Parked For Now

Keep these out of the active delivery phases until the core is clearly stable:

- Project Repo Bridge
- Launchpad
- NE Obsidian Sync
- cloud sync
- login and account systems for V0.1
- live GitHub integration
- live WordPress integration
- live calendar integration
- heavy AI automation without a safe adapter
- native Bluetooth printing as the first label path

## Rule Of Thumb

If a new task does not clearly support one of these phases, park it and keep the queue focused.

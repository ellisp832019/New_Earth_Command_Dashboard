# Subsystem Status Audit

This audit gives a quick read on where each major part of the project stands right now.

## 1. Dashboard

Status: **Active and important**

What exists:
- local-first shell
- top 3 task flow
- quick capture
- daily focus surfaces

What is still needed:
- V0.1 release-readiness pass
- manual persistence testing
- inbox processing verification and polish
- project detail surfacing

Risk level: **Medium**

Reason:
- the core is working, but it still needs a release-level polish pass before wider growth

## 2. Module Hub

Status: **Stable for now**

What exists:
- module registry
- browsing and search
- detail views
- operations and governance
- docking preview and layout planning

What is still needed:
- live dock host
- persisted dock position
- first live docked module

Risk level: **Low to Medium**

Reason:
- the current slice is complete for now, and the future dock rollout can wait until the shell needs it

## 3. Voice

Status: **Active and being refined**

What exists:
- voice capture
- voice assistant flow
- wizard / briefing direction
- wake phrase handling
- shared session work

What is still needed:
- remembered thread polish
- briefing clarity
- follow-up chips
- reply tuning
- shared session verification

Risk level: **Medium**

Reason:
- voice is powerful and user-facing, so polish and state handling matter a lot before any AI expansion

## 4. Knowledge And Docs

Status: **Active support layer**

What exists:
- Knowledge Library PDF scanning
- catalogue work
- Repo Intelligence Bridge templating
- Obsidian sync cleanup

What is still needed:
- richer search and filters
- per-item manifests
- failure handling
- consistency across template profiles

Risk level: **Low**

Reason:
- this layer is already useful and mostly needs steady refinement rather than structural change

## 5. Assets And Treasury

Status: **Active operational layer**

What exists:
- assets and QR label flow
- treasury workspace

What is still needed:
- print queue reliability
- receipts and evidence links
- location and bin mapping

Risk level: **Medium**

Reason:
- it handles real-world operations, so reliability and traceability matter

## 6. AI And Integrations

Status: **Parked for later**

What exists:
- roadmap intent only

What is still needed:
- AI adapter contract
- local stub provider
- opt-in settings
- integration gates

Risk level: **High if rushed**

Reason:
- these layers are intentionally future-facing and should not be forced into the core too early

## Overall Read

- The app is already more than a prototype.
- The best work now is hardening and release readiness.
- The most important future path is safe AI layering, not broad integration.
- Module Hub is stable enough to pause.
- Voice and Dashboard remain the highest-value near-term polish areas.

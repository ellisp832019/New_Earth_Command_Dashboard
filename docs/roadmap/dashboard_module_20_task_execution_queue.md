# Dashboard Module 20-Task Execution Queue

This is the practical build queue for bringing more modules online with the core Dashboard.

It is ordered to reduce risk:

- first stabilize the operating core
- then activate the safety and capture lanes
- then bring knowledge and coordination tools online
- then leave expansion modules for the end of the queue

## Queue

### 1. Treasury folder health and path visibility

Make Treasury clearly show whether the local finance folder is available and healthy.

Outcome:

- the user can see the finance path and readiness state before doing anything else.

### 2. Treasury resumable draft and wizard flow

Make the weekly finance ritual resume cleanly from the last saved local draft.

Outcome:

- Treasury feels safe enough to return to without losing work.

### 3. Treasury summary and decision surfaces

Surface Safe, Watch, Pause, and Needs Decision states clearly on Treasury screens.

Outcome:

- Treasury becomes an active operating lane, not just a file editor.

### 4. Voice Assistant capture history

Expose recent voice captures so a command can be reused instead of repeated.

Outcome:

- the voice surface becomes practical for daily reuse.

### 5. Voice Assistant remembered thread and briefing flow

Keep the current voice thread visible and make the briefing explain the next step more clearly.

Outcome:

- the assistant can continue a conversation without losing context.

### 6. Voice Assistant shared session state polish

Keep wake, dock, and assistant behavior aligned through one session model.

Outcome:

- the voice flow feels like one system instead of several competing surfaces.

### 7. Backup Guardian history and restore point surfacing

Make recent backup activity, restore points, and verification status easy to read.

Outcome:

- backup status becomes obvious and boring in the best way.

### 8. Backup Guardian open-folder and report actions

Make it easy to open the mirror folder and the latest report from the dashboard.

Outcome:

- the backup module becomes self-serve and easy to trust.

### 9. Asset Intelligence config and health check

Add the local asset path to config and validate it from the dashboard.

Outcome:

- Asset Intelligence has a trustworthy source path and health signal.

### 10. Asset Intelligence home and register views

Build the calm asset home and the first useful register views.

Outcome:

- the module becomes visible and navigable instead of hidden in planning docs.

### 11. QR Labels generation and label preview

Generate labels from asset id, show preview, and keep the flow manual first.

Outcome:

- labels are useful before printer automation exists.

### 12. QR Labels print queue and printer profiles

Add the queue and the profile data without jumping straight to Bluetooth printing.

Outcome:

- QR output can be managed safely and predictably.

### 13. Visual Capture inbox and import flow

Create the capture inbox and allow files to be imported into it.

Outcome:

- photos and receipts have a calm landing place.

### 14. Visual Capture linking to Treasury and Assets

Allow captured images to link to finance, assets, projects, and QR labels.

Outcome:

- capture becomes operational evidence, not just storage.

### 15. Knowledge Engine library page and health view

Show the library page inside the Dashboard with health and extraction progress.

Outcome:

- the knowledge module becomes visible as a real working surface.

### 16. Knowledge Engine search and item detail

Add search and a single-item detail view.

Outcome:

- the library can actually be used, not just scanned.

### 17. Repo Research Engine dashboard page and report viewing

Surface repo research in the Dashboard and make report reading easy.

Outcome:

- repository analysis becomes an accessible review tool.

### 18. Repo Research Engine comparison and review flow

Expose comparison, change tracking, and follow-on review actions.

Outcome:

- repo analysis supports understanding across versions and projects.

### 19. Meeting System file-first index and note flow

Create the local meeting index, meeting notes flow, and core action/decision capture.

Outcome:

- meetings become structured local records instead of loose notes.

### 20. Command Deck software page and quick-launch actions

Bring the software deck online as a calm launcher for useful actions across the core system.

Outcome:

- the Dashboard gains a speed layer that helps operate the rest of the modules.
